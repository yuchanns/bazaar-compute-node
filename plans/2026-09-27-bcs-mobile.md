# BCS 桌面与手机共用页面适配

## 问题与目标

现有 BCS 使用固定宽度多栏布局。390px 手机屏幕中，56px 导航和一个 300px 列表已占去大部分空间，智能体页面还可能同时存在两个列表；详情、配置表单和 520px 创建向导无法正常展示。

改造现有模板、组件和样式，使同一个页面在桌面展示多栏，在手机按层级展示单栏。用户可以从列表进入详情、返回上一层，在手机完成会话审核、管理电脑、创建与配置智能体、调整设置。宽屏保留原有工作方式。

## 效果与讨论结论

[完整效果稿与页面索引](2026-09-27-bcs-mobile/README.md) 包含 36 个页面及状态、6 张浅色总览、主要页面深色总览、逐页 PDF 和离线交互 HTML。

- 复用现有模板、图标、配色、卡片及表单。布局通过媒体查询适配，页面数据和业务操作继续走现有路由。
- 手机全局导航放到底部，包含智能体、电脑、设置；退出登录入口放在手机设置页。
- 智能体列表 → 会话列表 → 会话内容逐层进入；电脑列表 → 电脑详情同样处理。详情页顶部有返回入口。
- 会话和待审核标签同时保留 `message-circle`、`user-plus` 图标、文字和数量提示，选中时统一高亮。
- 登录按钮左对齐、按内容确定宽度，效果稿采用最小宽度 72px、高度 42px。
- 长配置纵向滚动；新建智能体向导在手机使用全屏容器，四步共用现有表单和脚本，底部操作始终可见。
- 会话记录保持现有只读用途；成员和提醒使用现有会话信息组件，在手机占满内容区域。

效果稿是设计参考，独立 HTML 文件代表不同展示状态。实施时把这些状态接入现有页面及局部刷新流程。

## 布局与导航实现

### 共用结构与断点

以 `max-width: 959px` 作为单栏布局起点，960px 及以上使用桌面多栏。该值为本计划的初始实现值：两个 300px 列表、56px 导航和可读详情区决定了窄屏必须切换层级。验收覆盖断点两侧及横屏。

`rail.html` 保持一份导航结构，增加可见文字与对应的无障碍名称；桌面竖排、窄屏横排，退出操作在手机设置目录可达。`shell.html` 使用动态视口高度，主区域设置 `min-height: 0`，底部考虑 `env(safe-area-inset-bottom)`；列表、详情正文、聊天和向导正文分别负责自身滚动。

共享标题组件支持显式返回链接，窄屏显示返回按钮，桌面保持既有标题布局。按钮有可读名称与焦点样式。文本输入在手机至少 16px，常用触摸目标约 44px，登录按钮采用已审阅的 42px 高度。

### 活动层级与 URL

完整页面由路由语义确定手机活动层，不单凭是否存在 selected 判断：

| 入口 | 手机活动内容 | 返回 |
| --- | --- | --- |
| `/agents` | 智能体列表 | 全局导航 |
| `/agents/{computer}/{agent}` | 会话或待审核列表 | `/agents` |
| 现有 contact URL | 会话内容或审核卡 | 对应智能体列表页，保留 review 查询状态 |
| 现有 profile URL 与 tab | 智能体详情 | 智能体列表 |
| `/computers` | 电脑列表，即使服务器预选首台电脑 | 全局导航 |
| `/computers/{computer}` | 电脑详情 | `/computers` |
| `/settings` | 设置目录，即使默认 section 为 appearance | 全局导航 |
| `/settings/{section}` | 对应设置表单 | `/settings` |

为模块内容和各栏添加明确的 `data-*` 状态，后台只表达当前路由所指层级，屏幕宽度由 CSS 决定。完整渲染时直接写出状态；局部 `#chat` 替换后从返回片段的状态更新所属模块，避免完整模块与片段两种进入方式出现差异。可采用模板事件或一个共用静态脚本，监听本仓库已有的 htmx 内容处理与 history 更新事件，集中处理层级同步。

点击会话/待审核时，同时保持标签选中、查询参数和返回目的地一致。审核通过进入会话，拒绝后使用服务端已有的 `HX-Push-Url` 回到联系人层；直接打开、刷新、浏览器前进后退都应恢复相同状态。电脑详情轮询、联系人刷新、消息追加和 profile tab 替换保持当前活动层及合理的滚动位置。

返回链接使用明确父级地址；浏览器自身前进后退交给现有 history 流程。检查 `HX-History-Restore-Request` 与 Renderer 的整页/片段选择，保证恢复目标拿到完整所需内容。屏幕改变只切换布局，继续保留当前选中对象与表单输入。

### 表单、弹窗和内容

- 修改 `agent_form.html` 共用卡片和字段的响应式样式，窄屏标签在控件上方；卡片切换按钮在触摸设备持续可见，保持 `.shown` 和现有增删逻辑。

仓库 `resources/static/htmx.min.js` 声明 **4.0.0**，`shell.html` 默认 `innerMorph`。已读取官方 `htmx.org@4.0.0/dist/ext/hx-alpine-compat.js`：扩展在 swap 前延迟 Alpine mutation 处理，在 after-swap / finally-request 中释放，并在 morph 时继承 Alpine data stack。其行为以该发布版本源码为准；文档安装示例仍含 beta6，资源按仓库的 4.0.0 配套获取。

- [htmx Alpine 集成扩展](https://four.htmx.org/extensions/hx-alpine-compat/)：加载顺序为 htmx、配套扩展、组件注册脚本及插件、Alpine 核心；组件注册监听 `alpine:init`。由官方扩展负责 htmx morph 与 Alpine 生命周期衔接。
- [Alpine.data](https://alpinejs.dev/globals/alpine-data)：复用组件用命名 provider；`init()` 初始化组件，`destroy()` 清理计时器、observer 和在途请求。组件脚本独立随包加载，模板调用简短方法与绑定。
- [x-model](https://alpinejs.dev/directives/model)、[x-for](https://alpinejs.dev/directives/for)：字段和列表由数据驱动；动态行使用稳定唯一 key；卡片的显示名称、字段、环境变量和摘要来自同一份编辑数据。
- [Alpine.bind](https://alpinejs.dev/globals/alpine-bind)、[x-modelable](https://alpinejs.dev/directives/modelable)：重复控件行为用绑定对象收敛；确实需要独立子组件的字段通过 modelable 与父级交换值。简单字段直接绑定父级数据。
- [Focus](https://alpinejs.dev/plugins/focus)：`x-trap` 支持嵌套焦点限制与逐层返回；弹窗结合 `.inert`、`.noscroll`，以及 `$focus` 完成初始焦点和校验定位。
- [事件](https://alpinejs.dev/directives/on)、[$dispatch](https://alpinejs.dev/magics/dispatch)、[$nextTick](https://alpinejs.dev/magics/nextTick)：使用 `.outside`、键盘修饰符、组件事件和响应式渲染后的时机表达交互。关闭最上层确认框时由事件传播范围保证外层抽屉仍打开。
- [Collapse](https://alpinejs.dev/plugins/collapse)：文件夹内容在 `x-show` 控制下使用 `x-collapse` 展开和收起，结合 reduced-motion 偏好。视口滚动与动态高度交给浏览器和插件。

### 组件边界与数据约定

htmx 继续承担 HTML 请求、提交、轮询、局部替换、URL 和历史导航；Alpine 承担组件本地可变状态、派生显示及交互生命周期。路由选中对象由服务器决定，组件根使用对象身份区分：同一个对象刷新时保持编辑状态，切换智能体/会话时创建对应的新状态。完整页面、局部插入、morph、前进后退分别验证。

Alpine 本地状态随所在组件销毁；表单凭据和环境变量值只参与当前表单编辑与提交。继续采用现有服务端历史恢复流程，避免将表单状态序列化进浏览器历史缓存。服务端已有凭据仅提供“已设置”标记；摘要显示设置状态和变量名称。

每个 DOM 区域有明确的状态来源：服务器返回页面与业务数据；动态卡片及环境变量行由 Alpine 的带 key 列表渲染；htmx 请求更新被指定的服务端片段。错误响应需明确恢复的字段、卡片来源和当前步骤，与客户端状态一次对齐，保证后续输入、提交和服务器读回一致。

现有原生能力继续在对应组件方法中使用，例如表单 `checkValidity/reportValidity`、Clipboard、滚动尺寸和原生 select。官方指令负责显示、列表、事件、焦点与生命周期；业务方法负责节点请求及业务规则。迁移完成时逐项登记剩余原生调用的用途，并删除被替代的旧控制逻辑。
