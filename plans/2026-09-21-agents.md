# 智能体管理

## 背景

节点启动时读一次配置，把里面的智能体全部拉起来；此后配置怎么改，都要 `bcn restart` 才生效。`bcn agent add` /
`bcn agent remove` 只改配置文件，改完提示重启；`bcn server connect` 也是。bcs 上看得到每台电脑上的智能体，但只是一列
行，不能新建、不能看它的配置、也不能改。

`plans/2026-09-15-bcs.md` 的线框图第 ③ 张画了智能体资料页：五个标签——配置、技能、工作区、状态、活动——配置可以
直接改；框架计划把「智能体管理」留到框架之上另行计划，就是这一支。要在 bcs 上新建与改配置，节点得先能在运行中
起一个新的智能体、停一个、把一个停了再起；这一支先把这层做出来，再把页面搭在上面。

同一支顺带把列表的样子定下来：智能体行改成单行、状态点挂在头像角上、属性图标靠右；副标题里的图标和文字按中线
对齐、间距统一，不再用「·」隔图标；电脑名不再显示，换成系统图标；电脑页上的智能体列表装进一个框。

## 目标

- 节点在运行中能新增、修改、删除一个智能体：配置与凭据落盘，进程内立即生效，不重启进程，其它智能体不受影响。
- bcs 的电脑页能新建智能体；智能体有资料页，配置能看能改，技能、工作区、状态、活动能看；能从资料页删除智能体。
- 凭据只从 bcs 送到节点一次，节点存进环境文件，不回显，不上报。
- 列表与标题按定稿的样子重排。

## 设计

### 节点：运行中的智能体生命周期

`NodeApplication` 现在把 `configuration.agents` 当成启动时的清单，`_start_agent` 只在 `start()` 里被调用。改成三个
运行中可调的方法，都以一份完整的 `AgentConfiguration` 为输入，都在同一把 `asyncio.Lock` 下顺序执行，免得两个改动交错：

- `add_agent(configuration, secrets)`：把凭据写进环境文件与 `os.environ`，配置追加到 `self.configuration.agents`
  并写回 `config.toml`，然后 `_start_agent`。启动失败照旧记进 `agent_startup_results`，配置不回滚——和启动时一个
  智能体起不来别的照常一样，失败的留在清单里，状态里看得到原因，改好配置再起。
- `update_agent(configuration, secrets)`：找到同 id 的智能体，`agent.stop()`，从 `self.agents` 摘掉，写凭据、替换清单
  里的那一份、写回配置，再 `_start_agent`。停与起之间这个智能体收不到消息；channel 停了 provider 那边的消息等重新
  长轮询后再拿到，落库不丢。
- `remove_agent(agent_id)`：`agent.stop()`，从清单与 `self.agents` 摘掉，写回配置。工作区与库里的数据保留，和
  `bcn agent remove` 一样；它引用过的环境变量名留在环境文件里不动——同一个 token 可能别的智能体还在用，清理是
  操作者的事。

`self.configuration` 从此是活的：`_health()` 已经按它列智能体，改完立刻反映；每次改动后 `health_reporter.report()`
主动发一拍，bcs 不用等下一个 60 秒心跳。三个方法各记一条审计事件 `agent.added` / `agent.updated` / `agent.removed`
（`state = completed`，metadata 带 `agent_id`、`name`、channel 与 runtime 的种类），失败的带 `error`。

配置写回复用 `app/config.py` 的 `_write_configuration`（序列化 + 原子替换）；环境文件复用 `server_management.py`
的 `_write_env_value`（一个名字一行，已有的替换，没有的追加，0600），两者都挪到各自模块的公开名字下。写进
`os.environ` 是因为插件在 `build` 时读 `os.environ[token_env]`：文件只在下次启动才被服务读进来。

凭据在配置里只以环境变量名出现（`token_env` / `app_secret_env` / `secret_env`），这一点不变。名字由节点起：
`BCN_<完整 AGENT_ID，- 换成 _，大写>_CHANNEL<卡片序号>_<CHANNEL 大写>_<键>`，如
`BCN_01A0C3EB_…_CHANNEL0_TELEGRAM_TOKEN`：id 用全的——UUIDv7 的前 8 位只是时间戳高位，一分钟内建的两个智能体会相同——
再带卡片序号，同一智能体两张同种 channel 也分得开；改凭据就是覆盖同名的值。`secrets` 是 `{channel 序号: {选项键: 值}}`，只有 bcs 送来的那些；没送的保持原值。
runtime 的环境变量同理：页面上填的是变量名和值，值由节点存进 `BCN_<完整 AGENT_ID>_RUNTIME<序号>_<RUNTIME 大写>_ENV_<变量名，大小写不变>`（`TOKEN` 与 `token` 是两个变量），
配置的 `env` 记下「变量名 → 这个存储用的名字」；`env` 是 `{runtime 序号: {变量名: 值}}`。名字先全部定下、配置先校验，
变量名放不进配置（不是合法的环境变量名）就整单拒收，一个值都不写。环境文件由 systemd 读、launchd 下被 sh source、
Windows 下被 PowerShell 点源，单引号字面量对三者都安全的前提是值里没有单引号、没有换行：含单引号、换行或 NUL 的值同样
整单拒收，不做转义。

`bcn agent add` / `remove` 的 CLI 不动：它们在节点没起来时也要能用，路径是改文件；节点起着的时候用 bcs。

### 节点：下行的读与写

`contrib/server/control.py` 的 `_Request` 添几种。到智能体级的仍经 `commands_of(agent_id)`；这一支新添的是节点级的
操作，`ControlContext` 多一个 `node: NodeCommands`——一个只有这几个方法的协议，由 `NodeApplication` 实现：

- `{"read": "setting", "agent_id", "key"}` 由节点直接从这个智能体的存储里读，与随 `agent` 写一起落盘的写法对称：
  没在运行的智能体也答得出，读不到与「设成空」不会混淆。
- `{"read": "agents"}`：清单里每个智能体的配置，凭据按 channel 逐张给「有没有值」（`secrets` 是与 `channel` 同序的列表，每项 `{键: 变量在 `os.environ` 里有值吗}`；
  只写了变量名而没有值的算没设，页面上那张卡就要求重填）；带 `kinds`：
  这台节点装了哪些 channel 与 runtime 种类（`AdapterRegistry` 从 entry points 列出来），供表单画下拉。
- `{"write": "agent", "agent": {...}, "secrets": {...}, "env": {...}, "settings": {"review.reply": ...}}`：`agent` 是一份完整配置的 JSON（有 `id` 就是修改，没有就
  是新建，id 由节点给；带着节点没有的 `id`——表单打开后智能体已被删——回 `TARGET_NOT_FOUND`，不当新建）；pydantic 在边界校验形状，`AgentConfiguration` 的构造再校验值，错了回
  `INVALID_REQUEST`。应答是写回后的那份配置（同 `agents` 读的一项）。配置落盘即回答，智能体在回答之后才启动，
  请求不等启动（启动可长达启动时限，不必让一次询问等它；bcs 的一次询问最多等一分钟，不跟着节点自己的时限走）：起没起来看它的状态，起不来时状态里有原因。
  启动进行中的智能体再来改动或删除一律拒收（「agent is starting」），不与启动并行。
  关停优先于一切：节点的整个关停在最外层只有一个时限（关停时限），不往各组件层层传，到点没做完的清理交给进程退出；
  bcs 同样，uvicorn 的优雅关停给关停时限，不等还开着的连接。停一个智能体时被取消，收尾之后把取消原样抛出，不吞成普通
  失败。
- `{"remove": "agent", "agent_id"}`。
- `{"read": "skills", "agent_id"}`：智能体的技能，问它的 runtime 本人：有会话开着就问那个进程，没有就在它的工作区里起
  一个临时进程问完就关；节点级的探测（版本、模型）只带平台变量（HOME、PATH、LANG 等）与该 runtime 自己声明的变量名，
  节点环境里各智能体的凭据与 bcs 的控制 token 一律不给；版本探测超时就杀掉子进程并等它退出。临时进程带这个 runtime 配的环境（`CODEX_HOME`、`CLAUDE_CONFIG_DIR` 这类决定个人技能在哪的
  变量），不带 bcc 的会话凭据（`RuntimeCommandContext.environment_for_probe`）。codex 发 `skills/list`
  （`{"cwds": [工作区]}`），应答 `data[]` 每项的 `skills[]`：name、description、interface.shortDescription、scope
  （repo / user / system / admin）、enabled，只取 enabled；scope repo 算工作区、user 算个人，其余算内置。claudecode
  发 `initialize`，应答 `response.commands` 每项 name、description、argumentHint，CLI 自带的带 `builtin`（不算技能，
  去掉）；其余看描述结尾的来源标记：`(project)` 算工作区、`(user)` 算个人（标记从描述里去掉），没有标记的（如
  `claude.ai sync`）算内置。每项 `name`、`description`、`source`（`workspace` / `personal` / `system`）。
- `{"read": "workspace", "agent_id", "path"}`：工作区里一个目录的一层清单（不回工作区在这台电脑上的位置）（`path` 相对工作区，空就是顶层）：
  名字、是文件还是目录、大小、修改时间，按名字排，每层最多 200 项，超出时 `more` 为真；`at` 回显列的是哪一层。符号链接不列（可能指到工作区外，也可能指向不存在的地方）。
  一次只读一层，页面点开哪个目录才读哪个；解析后（`..`、符号链接都算上）落在工作区外的路径拒收。读目录放线程里。
- `{"read": "runtimes"}`：节点装的每种 runtime 能不能跑、什么版本，问 runtime 本人。runtime 插件是一个
  `IRuntimeBuilder`：`build(context)` 造出 runtime，`inspect(timeout)` 说自己——命令在 PATH 上且 `--version` 能跑
  才算可用；`models(timeout)` 列模型。三个方法都是插件必须有的：entry point 指向这个对象，注册表按协议加载，缺一个
  就加载失败。答案留 60 秒：runtime 可能在节点不重启的情况下升级。每项 `kind`、`available`、`version`、`error`。
- `{"read": "models", "kind"}`：一种 runtime 能用哪些模型，只问这一种。codex 起一个临时的 `app-server --stdio` 发
  `model/list`（按 `nextCursor` 翻完），claudecode 起一个临时的 stream-json 模式 `claude -p` 发 `list_models` 控制
  请求（取 `value`、`displayName`、`supportedEffortLevels`），问完就停，不开会话、不发消息。回 `models`（`id`、
  `name`、`efforts`、`default_effort`、`default`）与 `error`（没列出来时的原因）。列出来的按种类留 60 秒，没列出来的
  不留，再问就再去问 runtime。没装的种类回 `TARGET_NOT_FOUND`。

状态与活动不加读取：状态就是心跳里那个智能体的 `channel_health` / `orchestrator_health`，活动就是它的事件，bcs 都有。

功能权限点按框架计划的规矩一项操作一个：新建 `agents.create`，改配置（含凭据、自动回复）`agents.update`，删除
`agents.delete`；资料页各 tab 的读取、技能、工作区、状态、活动都归已有的 `agents.view`；审核仍是 `agents.approve`。
root 一律为真，页面上按钮与路由各自带 `@allowed`，没有权限的按钮不画。数据权限点不变：能看这台电脑的账号才能
在它上面新建，能看这个智能体的才能改与删（`@sees`）。

### bcs：新建智能体

电脑页框下的 ➕ 打开一张 `.veil` 居中对话框，标题「新建智能体」，内容分四步：基础信息、渠道、运行时、确认。打开时
不问节点：节点要答的只在表单用到的那一处、用到时才问，转圈也只在那一处。

- 顶部是进度条：一条线串起四个点，点下写步骤名；当前一步实心加浅色外环，走过且填好的是对勾，走过但有必填项没填的是
  红圈「!」，没到的是空心。点可以直接跳；底部「上一步」「取消」「下一步」，最后一步「下一步」换成「新建」。
- 基础信息：名字、模式、空闲回收一张卡，下面「自动回复」一张卡（多行框，可留空；留空就是不自动回复）。
- 渠道、运行时：同一种的卡是一叠页，一次显示一张。卡片右上角是直角，右侧边缘贴一个与卡片顶部对齐的书签，中间细线
  分成上下两半（细折线图标），翻上一张、下一张；只有一页时不显示。最后一页是一张虚线的空白卡「添加渠道 / 添加运行时」，
  两列列出这台电脑装了的种类（标志、名字、运行时的版本；找不到的灰掉带黄色感叹号，hover「未找到」）。空白卡第一次
  露出来时才问节点（`GET /computers/<c>/kinds/<channel|runtime>`：渠道取 `agents` 读取里的种类，运行时取 `runtimes`
  读取），问的时候卡里转圈，没问到时写原因和「重试」。点一个种类，空白卡
  的位置换成该种类的新卡并显示出来；一张卡都没有时，这一步打开就是空白卡。卡片右上角垃圾桶删卡，删后显示它前一张。
  卡片标题、种类按钮里的标志按文字中线对齐。
- 运行时卡：模型与推理强度的下拉起初只有当前的值（没写就是「默认」）；两者任一第一次被点开时才问这种 runtime 的
  模型（`GET /computers/<c>/models/<kind>`，即 `models` 读取），问的时候那一栏右侧转圈，出错或超时换成刷新图标，
  hover 显示原因，点它再问；同一张表单里同种的卡共用一次问到的列表。列表第一项「默认」值为空——同配置里不写
  `model`，由 runtime 自己定；各 runtime
  标出它不指定时用哪个（codex `isDefault`，claude 值为 `default` 的那项，后者不再单列），「默认」的推理强度选项取那个
  模型的；配置里写着列表里已没有的模型时，照原样多列一项并选中，保存不改掉它；推理强度同样默认为空，换模型时之前选的
  强度新模型也支持就保留，否则回到默认；推理强度随所选模型的
  `efforts` 变，下拉里显示值本身、不翻译，模型不支持推理强度时这一栏隐藏。环境变量一行一项「变量名 = 值」，值是密码框；
  已经存过的一项只显示「已设置」和「更换」，不填新值就沿用原来的存储变量。
- 确认：只读摘要，一张卡一块；凭据只显示「已填写」「未填写」，开关显示「开」「关」，环境变量只列变量名，值不回显。
- 点「新建」时若有必填项没填，跳到它所在的那一步和那一张卡，再由那一栏自己提示。
- 一个智能体至少要有一个渠道和一个运行时：渠道或运行时一步一张卡都没有时，这一步的点同样是红圈「!」，但不拦着往下走；
  提交时 bcs 不下发，停在「确认」一步提示「至少添加一个渠道」或「至少添加一个运行时」。资料页保存同理，提示在按钮旁。

提交 `POST /computers/<c>/agents`，请求在路上时「新建」按钮锁住（`hx-disable`）。处理器下发 `agent` 写，有自动回复时随同
这一次写的 `settings` 一起下发——节点落盘时就把它写进这个智能体的存储，不等它启动，也就不是一条要单独问一个还在
启动的智能体的请求。成功后关对话框、框里的列表立刻再取一次；失败时对话框
留着、已填的内容保留、打开在「确认」一步，显示错误（`agents.offline` / `silent` / `refused`，节点拒绝的配置是
`agents.invalid`，显示 `code`）。

### bcs：资料页

`/agents/<c>/<a>/profile`（`?tab=` 定位 tab），从智能体行最右的齿轮进入，整页在智能体模块里占右两栏的位置——左栏还是
智能体列表，选中行不变。页头：头像（状态点挂在头像左下角，同列表）、名字、系统图标 runtime 图标 channel 图标；下面
五个文字 tab（`.switch` 的样式，文字不是图标），默认「配置」。tab 之间切换是 `hx-get /agents/<c>/<a>/profile/<tab>`
换内容区、地址推成 `?tab=<tab>`。内容是一张张 `--edge` 描边的 `.dialog` 卡片，不带阴影，标签 `--muted`。

- 配置：一整页，不分步。`{"read": "agents"}` 里这个智能体的那份，分块，每块一个小标题：基础信息（名字、模式、空闲
  回收，同新建）、自动回复（一句说明与多行框，留空就是不自动回复）、渠道、运行时。渠道与运行时是新建里的同一副卡叠
  （书签翻页、虚线空白卡添加、垃圾桶删卡），小标题已经说了是什么，卡上不再重复块名。已有的卡在表单里带着它在配置
  里的下标（`channel-N-was` / `runtime-N-was`），保存时改过的字段盖在原来那份上，页面上不显示的选项（如
  `allowed_chats`）原样保留：接了 bcs 的节点由审核决定谁能进，名单是没接 bcs 时的兜底。凭据一栏在已有卡上显示
  「已设置」小标签和「更换」，点了才出密码框，空着就是不改；新卡上照旧是必填的密码框。节点没装、但配置里用着的
  runtime 种类照样画卡，点开模型时说找不到。推理强度的下拉里是值本身（`low` / `high` / `max` …），不翻译，节点新出的
  取值不用等 locale。页面打开时只读 `agents` 与自动回复，卡叠的空白卡、模型下拉与新建里一样用到时才问；已有的卡只画配置里的种类，
  版本只在空白卡的种类按钮上。保存后只重读 `agents`。卡片之后「保存」「取消」；保存 `POST /agents/<c>/<a>/profile`，请求在路上时「保存」锁住，下发
  `agent` 写（带 `id`，自动回复随 `settings` 一起，留空就是停掉）；成功后表单回显节点写回的那份与「已保存」，列表跟着刷新（`agents-changed`）；
  失败时保留已填的内容，在按钮旁显示错误（同新建）。最底下 `--danger` 的「删除智能体」卡，先问一句（`.veil`），确认
  后 `DELETE /agents/<c>/<a>` 下发 `remove`，成功回到智能体模块首页（`HX-Push-Url: /agents`），失败时问句留着显示原因。
- 技能：`{"read": "skills"}`，按来源分三组——工作区、个人、内置——每行名字与描述；空时「没有技能」。
- 工作区：不显示工作区在电脑上的位置；小标题「内容」右侧一个刷新按钮（请求在路上时图标转），重新读整个 tab。下面
  是目录树：目录一行带向右的箭头，点开箭头转下、在它下面缩进一级列出它的内容（第一次点开才向节点要这一层，之后只是
  折叠展开）；文件行是图标、名字、大小、修改时间。一层超过 200 项时末尾写「只显示了前 200 项」，空目录写「空文件夹」。
- 状态：这个智能体在最近一次心跳里的样子，写给人看，形状同其他 tab。第一张卡一行「智能体」：已启动且 orchestrator
  没有后台失败是绿点「运行中」；已启动但有后台失败是红点「运行异常」，下面灰字逐条列出失败的环节与错误名；没启动是
  「未运行」，灰字写心跳里的状态原词；电脑已离线时只写「电脑已离线」，渠道卡不出——最后一次心跳已不是现在的样子。
  orchestrator 不单独成行。其下小标题「今日用量」一张卡：输入、输出、缓存命中，
  运行时给了价格时加费用（与头像悬停卡片同一份计算），今天没有用量就不出这张卡。下面小标题「渠道」，每个渠道一张卡（标志与名字）：
  连接（正常 / 异常，异常时灰字跟上状态原词）、机器人身份、连接于、最近活动（多久前）、最近错误（有才显示，红字）。
  各渠道上报的字段名不同，按种类取：Telegram 取 `state == ready`、`bot_username`、`started_at_s`、
  `last_update_at_ms`、`last_poll_error_kind`；飞书取 `state == connected`、`bot_name`、`connected_at_ms`、
  `last_event_at_ms`、`last_disconnect_kind`；企业微信取 `state == connected`、`identity`、`connected_at_ms`、
  `last_frame_at_ms`、`last_disconnect_kind`；其他种类只看 `state` 与身份。收发计数不展示。
- 活动：整个 tab 是一个框（`--edge` 描边、8px 圆角），框头「事件流」，框身 `--canvas` 底、占满剩下的高度、内部滚动。
  日志式最新在顶上，一行一条：时刻（到秒，等宽）、来源（事件名的第一段，原样，等宽灰字）、文案，附加的对象（工具名、
  会话名与发送人、用量）灰字跟在后面；`.failed` 结尾的事件文案用 `--danger`；行间没有分隔线。一天的事件与上面那行
  不是同一天时，前面插一条居中写日期的细线；最上面一组是今天的就不标。一页 50 条，滚到底自动加载更早的一页（不可见
  的 `.edge`，`?before=<事件 id>&above=<上一行的日期>`）。顶部每 5 秒带着最新一条的 id 问一次（`?after=<事件 id>`，从这个 id 往后按顺序取一页，
  两次之间多于一页也不漏，下次接着取），
  新行插在最前面、底色 `--hi` 淡出一次；最上面一组还没标日期时一并带上它的日期（`below`），跨过午夜时新旧两天之间也
  有日期线。事件不带联系人的 actor / target / channel，行上不做跳去聊天的链接。
- 自动回复的编辑从联系人栏挪到配置 tab，联系人栏的「自动回复」tab 与它的弹框去掉。

## Tasks

### Task 1：运行中的智能体生命周期

`NodeApplication.add_agent` / `update_agent` / `remove_agent`，改动锁，配置与环境文件的写回，`os.environ`，主动心跳，
三条审计事件；`_write_configuration` 与 `_write_env_value` 的公开名字。测试用真实 sqlite 节点：起着的节点加一个
智能体后它在 `agents` 与心跳里、配置文件里多了它、环境文件里有它的变量；改它的配置后是新的实例（旧的停了、
新的 `started`）；删掉后清单与心跳里没有它、别的智能体不受影响；起不来的记 `failed` 但留在清单里。

### Task 2：下行的读与写

`NodeCommands` 协议与 `ControlContext.node`，`_AgentsRead`（含 `kinds`）、`_AgentWrite`、`_AgentRemove`、
`_SkillsRead`、`_WorkspaceRead`、`_RuntimesRead`，runtime 插件协议 `IRuntimeBuilder`（`build` / `inspect`）与两个插件的 `inspect`，pydantic 边界，`RESULT_TOO_LARGE` 照旧。
测试用真实 bcs 与真实节点：下发新建后节点上多了一个智能体且应答里凭据只有「已设置」，下发修改后名字变了，下发
删除后没了；工作区读得出；模型与技能列表归 e2e（要真的 codex / claude）。

### Task 3：列表

智能体行单行与角标状态点（处理中呼吸）、副标题 flex 对齐、系统图标替换电脑名（`AgentView.system`）、电脑页的框与 ➕ 的壳（这一
task 里 ➕ 先只画不接）、活动占位图标去掉、表单控件的统一样式与开关、飞书标志、CSS。测试：行里没有电脑名、有系统
图标、状态点在行元素上；框存在。新建电脑改为弹框，保存后跳到详情页、接入命令卡在正文顶部；测试：表单在 `.veil` 里、空名
字留在弹框、保存后推送地址与选中行、详情页刷新里 `#connect` 为空。

### Task 4：新建智能体

➕ 的对话框、配置表单（与资料页共用的模板：卡片、种类菜单、环境变量列表、模型与推理强度的下拉）、
`POST /computers/<c>/agents`、`agents.create`、错误文案与两种语言的词。测试：表单提交
后节点上多了智能体，电脑页的框里出现它；节点拒绝的配置在对话框里显示错误。

### Task 5：资料页

`/agents/<c>/<a>/profile` 与五个 tab、智能体行的齿轮入口、配置的保存（`agents.update`）与删除（`agents.delete`）、
技能、工作区、状态、活动、自动回复的迁移。测试：五个 tab 都能打开；改名字保存后页头与列表都是新名字；删除后回到智能体模块首页且列表里没有它；
活动 tab 列出事件、往下能翻页。

### Task 6：真实运行验证

在 bcs 上给一台起着的电脑新建一个 Telegram 智能体（真 token），它立刻在线、能回私聊；在资料页改它的模型保存，
它继续在线且下一轮用新模型；删除它，bot 不再回复，配置文件里没有它，节点进程没重启过。

## 验收标准

- 新建、修改、删除都不重启节点进程，别的智能体的会话不中断。
- 凭据不出现在配置文件、审计事件、bcs 的库或页面里；只在环境文件和进程环境里。
- 资料页配置 tab 显示的就是节点配置文件里的那份，保存后两边一致。
- 列表按定稿：单行、角标点、右侧图标、无「·」隔图标、系统图标代替电脑名、电脑页的框与 ➕。
- 全站的输入框一个样、下拉一个样、开关一个样；亮色与暗色都对。
- 页面上没有英文的配置值和键名——除了模型 id 这种本来就是名字的。
