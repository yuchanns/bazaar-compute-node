# Bazaar contrib 市场

## 目标与阶段

web 组合提供 Bazaar contrib 市场页面，读取官方及用户追加的模块索引，展示登记的包名和 Python 包源，
用户选择目标宿主后交给该宿主的 uv 安装。安装完成后展示包提供的模块入口，配置并管理启用实例。
Bazaar 本身是页面模块，通过公共 UI、HTTP、身份和控制契约接入。
发行包为 `bazaar-contrib-bazaar`，模块入口为 `bazaar`，挂载于 `ScopeKind.ROOT`，纳入 bazaar-contrib-web 的页面组合。
页面依赖 server 提供的 API、gui 提供的 UI，以及 access、fleet 和模块管理的公共服务；公共契约由 HTTP／GUI 等所属包导出。

本阶段位于 [路线图](roadmap.md) 的 web 页面与配置 UI 之后。
[首阶段](framework.md) 提供共用索引与安装管理服务；注册入口、节点管理、remote／audit-sync／control、
server API、身份与页面阶段提供远端调用和交互能力。本阶段将这些契约组合为市场用户流程。
配置统一使用 V5，经目标宿主复用的配置包公共加载／提交逻辑与 CONFIG_STORE 读写；
app 提供启动输入和默认资源，core 的统一运行接口执行目标宿主的发现、自举装配与生命周期。载体自举见 [配置载体与启动自举](framework.md#配置载体与启动自举)。
版本转换与保存规则见 [框架计划](framework.md#v5-配置与版本转换)；
语言服务、默认英语和中文独立后端见 [语言服务与后端](roadmap.md#语言服务与后端)。
公共分支与发行规则见 [总计划](README.md)。
本地开发将市场、页面及其未发布依赖加入 [源码 workspace](README.md#本地-workspace-开发)，用 editable 组合联调；
包安装、升级与发行验收仍使用真实索引、独立 wheel 和隔离目标环境。

## 模块索引与 Python 包源

模块索引是包的安装清单，官方索引由 BCN 仓库的 `contrib/catalog.json` 提供，
默认地址为 `https://raw.githubusercontent.com/yuchanns/bazaar-compute-node/main/contrib/catalog.json`。
每个宿主的配置文档通过 contrib_indexes 保存订阅列表；以下是默认 filesystem 的 TOML 表示：

```toml
version = "5"

contrib_indexes = [
    "https://raw.githubusercontent.com/yuchanns/bazaar-compute-node/main/contrib/catalog.json",
    "https://contribs.example.com/catalog.json",
]
```

首次配置带入官方地址，用户可在 CLI 或页面追加、移除索引 URL。每份索引采用相同 JSON 结构：

```json
{
  "contribs": [
    {
      "package": "bazaar-contrib-logging",
      "source": "https://pypi.org/simple/"
    },
    {
      "package": "bazaar-contrib-pg",
      "source": "https://packages.example.com/simple/"
    }
  ]
}
```

| 字段 | 含义 | 使用位置 |
| --- | --- | --- |
| package | Python 发行包名 | uv 依赖要求与已安装发行包对应 |
| source | Python 包源 URL，如 PyPI 或私有 Simple API 地址 | uv 的包来源绑定、后续升级 |

索引读取边界使用 Pydantic 校验 JSON、包名和源 URL。索引 URL 标识安装清单，
条目的 `source` 标识 Python 包源，两者在页面及记录中分别展示。
每个条目的包名和安装源即可支持选择安装；版本、依赖、平台产物和下载地址由 uv 解析。
用户可保留默认版本选择，或在安装请求中填写版本范围。

页面展示订阅索引中的登记条目并按来源筛选。同一发行包和包源重复登记时合并展示，保留所有索引来源；
同名包来自不同包源时分别列出，操作使用用户选中的 `package/source` 组合。
同一宿主的同名发行包对应一个安装来源，用户改选其他来源时更新该包的候选声明，经完整组合解析后替换。
目录条目通过发行包名匹配已安装元数据，再结合依赖清单显示所选包源。
包名、版本、入口和描述等安装后信息从目标宿主读取，索引作者只维护安装清单。

索引内容由目标宿主管理服务读取和缓存，记录读取时间与成功状态。
离线或读取失败时展示已有缓存及更新时间，并提供重试；读取失败的索引单独显示原因。
修改订阅列表在保存后用于后续索引读取；已安装依赖的包源与运行配置继续保留。
维护者发布模块时更新包产物和入口声明，再将包名与安装源登记到相应索引。

## 包、入口与运行配置的对应关系

索引中选择的是发行包，运行配置中选择的是该包声明的 entry point。
公共 group 为 `bazaar_compute_node.contribs`，例如 PG 包的 `pyproject.toml`：

```toml
[project.entry-points."bazaar_compute_node.contribs"]
pg = "bazaar_contrib_pg:pg"
```

安装后，目标宿主通过 `importlib.metadata` 得到：

```text
bazaar-contrib-pg → 入口 pg → bazaar_contrib_pg:pg
```

发行包、版本、入口名和导入对象来自发行元数据，包源来自依赖清单。
同一个发行包可以提供多个入口，页面安装成功后展示入口列表及可用配置表单。
管理服务通过目标解释器加载入口定义，取得 Pydantic 配置模型、声明的 scope 类型、服务依赖及模块 API 要求。
用户选择入口并填写参数，统一保存到目标宿主顶层 contribs。模块类型作为说明展示，实例由宿主自动创建。

| 数据 | 保存和读取方式 | 用途 |
| --- | --- | --- |
| version | 配置文档的结构版本，0.3 使用 "5" | 沿历史版本链转换并校验后保存 |
| contrib_indexes | 所选载体中文档的 URL 列表 | 读取用户订阅的安装清单 |
| 额外依赖清单 | 宿主管理服务持久化包名、包源、版本范围与实际安装结果 | 安装、升级、卸载的完整候选组合 |
| 包元数据 | 目标 Python 环境的发行包及 entry points | 将包关联到入口、导入对象和实际版本 |
| 启用配置 | 所选载体中文档的顶层 contribs 与 contribs.config | 按类型和运行实体自动创建实例、装配服务 |
| 配置载体与修订 | 目标宿主的启动选择、当前 CONFIG_STORE 与快照修订 | 读取、校验后条件提交，冲突时刷新候选 |
| 运行实例 | 宿主自动创建，管理接口返回句柄与状态 | 查询运行状态及所属资源 |

filesystem 手写 config.toml、CLI 配置命令和页面编辑使用同一模型；页面与 CLI 经目标宿主当前的 CONFIG_STORE 保存。
载体入口和连接参数由目标宿主启动 flags 决定，版本链由发行自举组合决定，页面展示所选来源及修订；普通业务启停编辑完整文档中的 contribs。
配置中心入口的连接表单来自其作者的 Pydantic 模型，部署启动输入按该模型提供参数。
新载体包安装后展示其 CONFIG_STORE 能力与模型，切换载体由部署方更新启动输入并重启目标宿主。
卸载检查包括当前自举选择对载体包的引用；仍在使用时返回该引用和需要先调整的启动选择。
用户只填写入口与参数，实例上下文由模块 scope 和已有运行实体确定，运行标识由宿主生成。
编辑已有条目时更新顶层原条目，停用时从统一启用列表移除；包安装状态和配置状态分别展示。
一条 AGENT 配置可对应多个运行实例，页面分别显示所属 agent 与状态，实例详情关联同一个配置来源。
保存请求校验完整候选配置的模型、模块类型及实际实体展开后的服务依赖，使用编辑时的修订条件提交，成功后展示待启动的变更。修订冲突时展示配置已更新，重新读取并让用户核对候选后再校验提交。
实际服务在下一次宿主启动时按依赖进入 lifespan，已运行状态与新保存配置分别记录。

## 默认数据库与切换 PG 的页面流程

首次创建节点配置，经 CONFIG_STORE 提交 app 资源中的默认 `storage`、`sqlite`、`database`，
其中 `database.config.backend="sqlite"`。启用 server／web 保留节点的原存储条目；服务端在独立 ROOT 从自己的 BCS 配置选择后端和数据源。
运行时各自建立依赖图与 DB 服务。下列 PG 切换流程作用于所选节点的存储。
完整默认配置与生命周期写法见 [框架计划](framework.md#默认配置生成与后端切换)。

页面切换 PG 时执行以下步骤：

1. 选择目标宿主，从索引条目选中 PG 包与包源，提交安装请求。
2. uv 成功安装后，页面从发行元数据展示该包的入口，用户选中 PG 入口并填写连接参数。
3. 在同一目标作用域编辑已有 `database` 条目，将 `backend` 改为 PG 登记的后端名。
4. 保存包含 PG 启用条目与 database 更新的完整候选配置，避免重复追加 database 条目。
5. 下次宿主启动时先启用注册表，再启用选中的 PG 后端，随后启用 database、schema 和业务。

对应保存内容为：

```toml
# config.toml 中新增的 PG 条目，以及已有 database 条目的修改结果。
[[contribs]]
contrib = "pg"
[contribs.config]
dsn = "postgresql://localhost/bcn"

[[contribs]]
contrib = "database"
[contribs.config]
backend = "pg"
```

此片段与同一作用域已有的 `storage` 条目一起使用。用户保留 SQLite 条目时，两个后端各自持有连接，
业务使用 database 选择的 PG；用户停用 SQLite 时移除其启用条目，下次启动按新配置创建资源。
入口名 `pg` 由包的 entry point 声明，后端名 `pg` 由存储注册声明，两者分别用于加载模块与选择连接。
业务通过共享 `DB` 调用显式数据操作，接口与查询代码随业务模块管理。

配置校验能定位所选后端缺失、同名后端冲突和重复 DB 选择入口，错误包含模块入口、配置位置、作用域与服务 key。
默认选择、连接参数、SQLite 是否继续启用和额外 PG 包来源在整体升级中保留。

## 语言后端与旧配置升级

首次 V5 配置启用 bazaar-contrib-language 的 languages、language，明确 language.config.backend="en"。
languages 附带英语实现，功能模块携带各自的英语资源；中文是可选发行包 bazaar-contrib-language-zh-cn，
通过 language-zh-cn 入口登记 zh-CN 后端。

页面切换中文时，先在目标宿主安装中文包，启用其入口，再更新已有 language 条目的 backend="zh-CN"，
保存完整候选配置。languages 与英语回退继续可用。下次启动的 CLI、agent 通知与页面通过同一 LANGUAGE 渲染；
页面请求语言由 GUI 在已登记语言中协商，未命中使用配置默认值。
切换其他语言使用相同流程，入口和语言标识从发行定义与服务声明取得。

```toml
# V5 config.toml 的中文启用条目及已有语言选择。
[[contribs]]
contrib = "language-zh-cn"

[[contribs]]
contrib = "language"
[contribs.config]
backend = "zh-CN"
```

包安装、后端启用和默认语言选择分别显示；重复编辑更新原 language 条目，导入 server／web 组合保留当前选择。
卸载正在使用的语言包时列出需要调整的语言选择和启用条目，候选配置校验包含所选后端的服务依赖。
部分译文缺失时由 LANGUAGE 使用该功能的英语资源；后端未启用时配置操作给出依赖诊断。

目标宿主仍使用旧配置时，升级预检展示目标 V5、能力参数迁移和所需包。
旧 lang="zh-CN" 产生中文包需求，加入保存来源的完整 uv 候选组合，安装及模型／依赖检查成功后经当前载体保留原配置、条件提交 V5。
原 lang 缺省时由目标节点按旧语言规则解析一次后保存，新建 V5 默认英语。
其他语言标识保留为选择，缺少对应后端时显示安装／选择需求，转换结果继续保留 agent／provider、凭据引用、
DB／语言选择、连接参数和关闭版本检查的设置。原文档版本、旧／新修订、载体备份或历史位置及迁移结果由目标宿主记录。
页面展示所需操作与配置转换结果，目标宿主的配置入口复用公共加载／提交逻辑，调用发行自举的 CONFIG_V5 服务完成转换，
经 core 的通用候选校验后通过当前载体提交。

server 启动时通过自己的配置载体直接读取独立的 ~/.bcs/config.toml，保留旧 BCS 配置结构与有效默认值。
服务端设置由服务端 CONFIG_STORE 保存；节点配置管理通过所选节点的接口读取与提交 BCN 主配置。
升级预检展示独立 BCS 配置位置、数据目录、数据库与 session.key 路径，以及监听、保留期和登录时长；
使用原 ~/.bcs 资源，自定义配置路径继续遵循旧数据目录规则。升级后页面读取原账户、权限、历史与 refs，
BCS 设置编辑写回服务端自己的配置载体，节点设置写回所选节点载体，整体包升级保留双方资源归属；详见 [BCS 连续升级](framework.md#02-bcs-配置与数据源连续升级)。

## 管理服务与安装目标

市场消费 `bazaar-contrib-manager` 导出的 `ContribCatalog` 和 `ContribManager` typed 服务契约。
前者提供索引订阅、读取、条目列表、来源与缓存状态；后者提供已装状态、安装、升级、卸载、实例配置和启停。
CLI、server API 与节点 RPC 注册相应 handler，业务规则由同一管理服务执行。

页面始终显示当前目标：运行当前页面的节点，或已连接的指定远端 computer。
索引配置、依赖清单、Python 环境与节点运行配置均属于该目标宿主，节点配置由其节点 ROOT 的管理服务读取和保存。
本地节点请求通过节点提供的接口调用节点管理服务；远端请求经 control 与 remote 交给目标节点的同一管理服务。
服务端设置操作调用独立服务端 ROOT 的管理服务，使用 BCS 配置载体和 storage。
目标宿主使用自己的 uv、环境变更锁和配置存储，可信操作身份沿用 access 与 control 的规则。

安装与升级先解析完整候选依赖组合，按照保存的包源生成绑定来源的 uv 输入，
再消费同一解析产物完成实际安装。具体命令与 tool／专用 venv 规则见 [安装方案](framework.md#模块管理与自身-uv)。
添加额外模块保持宿主版本；整体升级同时解析目标 app、其同版 core／默认依赖及保存的 server／web 等可选包要求，
加入旧配置转换所需的中文／远程等包，并保留全部额外包版本要求、来源、实例配置与 DB／语言后端选择。
官方默认与可选包展示所属共同发行版本及实际安装版本；页面配置入口和参数。
已安装的官方可选包随 app 升级选择目标同版；显式固定版本和来源继续参与解析，冲突时显示具体约束。
官方包升级使用整体发行版本，第三方升级修改所选包的版本要求；卸载检查仍引用该包的实例及其他包的发行和服务依赖，
页面列出需要先停用或调整的条目。

包安装成功且入口与兼容信息确认后提交依赖清单；用户配置通过模型和依赖检查后单独保存。
候选组合解析失败时显示具体冲突包、版本范围或来源，原组合与运行配置保持为当前声明。
安装过程中失败时记录实际环境变更、原声明和恢复原组合的步骤，重试依据目标宿主的实际环境继续。
安装结果提供入口配置操作，用户在该步骤选择启用内容与参数。

## 页面与操作状态

Bazaar 页面通过 UI 注册机制挂载到 `/bazaar`，包含“索引”和“已安装”两个视图，共用目标选择器和模块详情。
索引视图提供订阅 URL 管理、条目列表、包源筛选、缓存状态与安装操作。
安装前详情展示索引 URL、包名、包源和版本要求输入；安装后补充实际版本、包描述、入口与兼容信息。
已安装视图展示包与所属组合、入口、配置实例及实际运行状态，提供参数编辑、启停、升级和卸载。

操作请求返回宿主自动生成的操作 ID，由目标宿主持有执行状态，页面通过 GUI 订阅或状态查询获取进度。
状态依次为排队、执行中、成功或失败；执行阶段展示依赖解析、下载与安装，配置保存使用对应配置操作。
页面刷新后按操作 ID 恢复展示，连接中断时保留最后状态，恢复连接后查询目标宿主结果。
重复提交相同操作 ID 返回同一操作记录，环境变更锁与节点升级共用。

成功结果分别展示已安装版本、配置保存状态和实际运行状态，待启动的变更标为“下次启动生效”。
当前节点与远端节点的操作均由所属宿主保留记录，重启后可以查询已完成操作的终态。
页面文本、错误、组件和资源通过 GUI 的 UI 注册机制接入，文本使用 bazaar-contrib-language 的 LANGUAGE 契约。
Bazaar 自持英语消息资源，中文等翻译来自已登记的语言后端。

## 本阶段的串行 Tasks

每个 Task 完成后停下 review，通过后继续下一个 Task，全部完成后合入 `0.3`。

### Task 1：索引与管理契约接入

- [ ] 接入首阶段的 package/source 索引模型及官方 catalog.json，完善维护与发布说明。
- [ ] 接入目标宿主的 contrib_indexes 配置、索引增删、条目列表、来源区分和缓存读取。
- [ ] 注册当前节点与远端节点的管理 handler，传递可信身份、目标和操作 ID。
- [ ] 使用真实官方与额外索引验证条目合并、同名不同源展示和目标宿主的已装状态，完成检查并提交 review。

### Task 2：索引与安装页面

- [ ] 注册市场页面、导航、目标选择器、索引管理、条目列表、来源筛选和详情。
- [ ] 接入所选包名、包源、可选版本要求、uv 安装、进度与结果展示。
