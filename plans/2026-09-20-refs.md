# 短链接：身份值的映射表

## 背景

bcs 的页面链接把每个对象的身份原样写进去：电脑与智能体的 id 是 uuid，会话是 `thread_id`、`actor_id` 与
`target`（`dm:<uuid>` / `group:<uuid>`），一条聊天记录的链接里有五个 uuid 再加名字，五六百字符。浏览器、反向代理
与 bcs 前面可能出现的任何一层都对 URL 长度有各自的上限，链接也不好读、不好收藏。

`plans/2026-09-18-contacts.md` 交付后，链接的形状已经定型，这一支只改它的长度：身份值在 bcs 内部换成短的，
界面上只见短的。

## 目标

- bcs 一张通用映射表：任何冗长的身份值都能换成一个短整数，并换回来。表不分业务——它不知道一个值是电脑、
  智能体、线程、actor 还是 target；哪个位置放什么，代码自己知道。
- 页面里的路径参数、查询参数与 DOM id 一律用短整数：`/agents/3/7/contacts/12?actor=9&target=15&…`。
- 消息 id（`latest`、`before`、`last`）不映射：它们每条消息一个，映射只会让表随消息数增长；链接里最长的就是它们。
- 节点侧不变：下行读取仍用原值，节点不知道映射的存在。

## 设计

### 映射表

`refs(id INTEGER PRIMARY KEY, value TEXT NOT NULL UNIQUE)`，新迁移 `v02_refs`。`id` 由 SQLite 自增分配，
一旦分配永不改变、永不回收：一个值在一台 bcs 上只有一个短号，重启不变，链接可以收藏。64 位整数不会用完；
一台 bcs 的电脑、智能体与会话加起来到不了百万，短号在六位以内。

不用雪花或随机串：这是登录后的管理界面，短号可猜没有关系；自增最短、最好读。表的本质是「按值查号」，号怎么
生成都要先落表，别的生成方式在这里没有收益。

`IStorage` 两个方法：

- `shorten(values: Sequence[str]) -> list[int]`：一批值换成短号，没有的当场分配（一条 `INSERT OR IGNORE` 多行，
  再一条 `SELECT` 取回），结果按传入顺序。
- `expand(ids: Sequence[int]) -> list[str | None]`：一批短号换回值，没有的位置是 `None`。

### 页面里怎么用

映射是单调的——一个值的短号不会变——所以进程内可以缓存：`refs.py` 的 `Refs` 持有 `dict[str, int]` 与它的反向，
`load(values)` 先补齐缓存里没有的（一次 `shorten`），之后 `ref(value)` 同步取号；`expand(ids)` 缓存里有的直接
给，没有的一次 `expand` 补上。缓存只增不删，大小就是这台 bcs 见过的身份值数。`Refs` 由 `create_app` 建一个，
交给页面对象与 `Renderer`：模板全局函数 `ref(value)` 就是它的 `ref`。

出链接：每个渲染列表或页面的处理器在渲染前把要进链接的值一次 `load`——智能体列表是每行的 `computer_id` 与
`agent_id`，联系人栏是每行的 `thread_id`、`actor_id`、`target` 加上所属的电脑与智能体，聊天记录是联系人与智能体
的那几个值。模板里写 `ref(agent.computer_id)`，值没有 `load` 过是 KeyError，测试会撞上。视图对象（`AgentView`、
`Contact`、`History`）不变，仍持原值。

进链接：路由的形状不变，路径参数与查询参数的内容换成短号；处理器在最上面一次 `expand` 换回原值，之后的代码
（`agent_view`、`contacts`、`latest` ……）照旧用原值。`@sees(kind, param)` 在校验前先 `expand` 路径参数——页面对象
都持有 `refs`，装饰器从 `self` 上取；短号不存在与不可见一样是 404。

- 路径：`/agents/<c>/<a>`、`/agents/<c>/<a>/activity`、`/agents/<c>/<a>/contacts`、
  `/agents/<c>/<a>/contacts/<t>`、`/agents/<c>/<a>/contacts/<t>/messages`、`/computers/<c>` 及其子路径。
- 查询：联系人与聊天记录链接里的 `actor`、`target`；列表刷新的 `selected`（智能体列表是 `<c>/<a>`，联系人栏是
  `<t>`）。`channel`、`name` 是显示用的短文本，原样。
- DOM id：行的 `id="agent-<c>/<a>"`、`id="contact-<t>"` 与 `hx-vals` 里从它们截出的 `selected` 一并换成短号；
  `id="message-…"` 是消息 id，不动。

## Tasks

### Task 1：映射表与 `Refs`

迁移 `v02_refs`；`IStorage.shorten` / `expand` 与 sqlite 实现；`refs.py` 的 `Refs`（缓存、`load`、`ref`、
`expand`）与 `@expanded`，`create_app` 建一个，`Renderer` 的模板全局 `ref`，页面对象持有它。测试用
真实 sqlite：同一个值两次 `shorten` 是同一个号，一批里新旧混合时顺序对得上，`expand` 没有的位置是 `None`，
重启（重新打开数据库）后号不变。

### Task 2：智能体与电脑模块

智能体列表、选中页、活动卡片，电脑列表、详情、在线状态、移除：路径、`selected`、DOM id 全部换成短号。
测试：页面里的链接不再出现 uuid，按短号打开的页面与按原值时一致，不存在的短号是 404。

### Task 3：联系人与聊天记录

联系人行、聊天列、`messages` 片段、边缘与尾巴的链接换成短号；`_contact` 从短号还原。测试同上：一次真实的
联系人 → 聊天 → 翻页 → 尾巴的链路，链接里只有短号与消息 id。

## 验收标准

- 一条聊天记录尾巴的链接不超过百余字符，其中最长的是消息 id。
- 同一对象在任何页面、任何时候的短号相同；bcs 重启后收藏的链接仍能打开。
- 节点侧与下行协议没有改动。
