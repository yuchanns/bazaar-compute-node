# BCS OIDC 登录与角色管理

## 目标

为 BCS 增加 OIDC 登录、多角色权限和按角色分享资源，沿用现有设置导航、详情页、移动端切换方式及 Lucide 图标。

- 一个账号关联多个角色，功能权限取角色授权的并集。
- 电脑和智能体分享给角色，分享时分别指定可执行的动作。
- OIDC 首次登录创建账号并分配当前默认角色；后续登录保留已有角色关联。
- 角色页管理名称、权限和默认状态；账号页统一分配角色。
- BCS 会话默认固定有效期 10 分钟，到期自动尝试一次免交互 OIDC 认证。
- 登录方式支持名称、图片上传和可编辑回调地址。

## 技术方案

### OIDC 与会话

采用 Authlib 1.8.0 和 httpx2 2.13.1，通过 uv 锁定依赖。依赖选用实施时最新稳定版。

[Authlib Starlette 客户端文档](https://docs.authlib.org/en/latest/client/starlette.html)提供 discovery、授权 URL、换取 token 和 ID token 校验接口。使用 `StarletteOAuth2App` 的协议方法，登录事务和应用会话由 BCS 管理。

按 [OIDC Core](https://openid.net/specs/openid-connect-core-1_0.html) 使用 Authorization Code、`openid profile email` 和 S256 PKCE；协议库校验签名、issuer、audience、有效期及 nonce。外部身份以 issuer 和 subject 唯一定位，显示名及 email 仅用于展示。

登录事务保存 state、nonce、PKCE verifier 和回调地址，并绑定浏览器 HttpOnly、SameSite=Lax cookie。换取 token 前原子消费事务，授权和换取 token 使用相同回调地址。账号创建、身份关联和默认角色分配在同一事务完成。

应用会话绑定账号 session_version；修改本地密码时递增版本。`session_minutes` 默认 10，服务端过期校验与 cookie Max-Age 共用配置，普通访问不续期。账号停用由身份提供方管理，在下一次 OIDC 认证时生效。

OIDC 登录成功后另设最长 30 天的签名恢复提示，记录账号、会话版本、提供方及 issuer/subject。该提示只用于重新认证，不授予业务访问权限。会话过期后校验并清除提示，再通过浏览器顶层跳转发起一次 `prompt=none`；回调身份必须与原身份一致。成功签发新会话和恢复提示，失败返回登录页，不循环重试。本地登录和主动退出清除恢复提示。

### 数据与存储

新增 v03 迁移，保留已发布 v01、v02。存储接口定义于 BCS `IStorage`，SQL 实现留在 SQLite 层。

| 数据 | 字段与约束 |
| --- | --- |
| roles | id、唯一 name、permissions JSON、created_at_ms、updated_at_ms |
| account_roles | account_id、role_id 联合主键，role_id 索引 |
| auth_settings | 单行 id、default_role_id |
| oidc_providers | id、name、logo_url、issuer、client_id、client_secret、redirect_uri、时间戳 |
| oidc_identities | issuer、subject 联合主键，account_id、provider_id、display_name、email |
| oidc_transactions | state 主键、provider_id、browser_hash、nonce、code_verifier、redirect_uri、预期 issuer/subject、expires_at_ms 及到期索引 |
| accounts 扩展 | auth_type（local/oidc）、session_version |

OIDC 账号使用独立账号 ID，内部 name 由 ID 派生，password_hash 为空；本地密码登录仅查询 local 账号。初始 admin 沿用现有初始化流程。

账号角色分配以事务整体更新关联。修改角色名称及权限不改变账号关联。删除角色清理其成员关联和资源分享；删除默认角色前先将其他角色设为默认。

Logo 通过 multipart 上传，Pydantic 在输入边界校验 MIME 和 256 KiB 大小上限，支持 PNG、JPEG、WebP、GIF。图片 data URL 保存在现有 logo_url 字段，随 SQLite 持久化；未上传时保留原图，支持更换和清除。

### 权限与资源分享

权限点集中注册于 `permissions.py`，标识同时作为中英文 i18n key，模块顺序决定表单展示顺序。

- 电脑：view、create、delete、share。
- 智能体：view、create、update、delete、approve。
- 设置：roles、accounts、oidc。个人外观设置由本人使用；安全页和修改密码接口仅允许 admin。

普通账号的功能权限取角色并集；资源动作还需满足 owner 或角色分享授权。admin 拥有全部功能权限和资源权限，不受所有者、角色或分享关系限制。角色分享动作不得超过操作者自身权限。

分享复用 `relations` 的 `computer_share_role` 和 `agent_share_role`，subject_id 为角色 ID，ext 保存权限点。合并账号各角色的资源授权后，与功能权限相交。查看电脑不自动授予其智能体的查看、审核或修改权限。

电脑分享仅授予 `computers.view`、`agents.create`、`computers.delete`；智能体分享独立授予 `agents.view`、`agents.update`、`agents.delete`、`agents.approve`。资源授权分别与功能权限相交，电脑分享不能授予已有智能体的权限。

电脑列表按电脑级查看权限过滤；智能体列表包含单独分享的智能体及展示所需的电脑信息。分页在授权过滤后进行。页面、控制端点和所有轮询主题共用访问规则；请求内缓存权限集合，下一请求重新读取，轮询摘要包含权限变化。

## 页面与路由

- `/settings/roles`：纵向角色列表与详情、新建、权限分组、默认状态和删除。权限横排自动换行；默认状态与说明文字基线对齐。默认角色隐藏删除按钮，其他角色使用标题栏 Lucide 删除按钮。
- `/settings/accounts`：账号列表、身份来源和角色多选。已选角色以可移除标签展示，下拉内搜索和勾选，保存后更新账号关联。
- `/settings/oidc`：提供方列表及名称、Logo、issuer、client ID、secret、回调表单。Logo 使用预览与 Lucide 选择、更换、移除控件，隐藏原生文件输入。secret 不回填，留空保留。缺少默认角色时提供设置入口并阻止新增登录配置。
- `/login`：保留本地登录表单，增加带名称和 Logo 的 OIDC 按钮。
- `/login/oidc/resume`：校验恢复提示，发起一次免交互认证。
- `/login/oidc/{provider_id}`：创建浏览器绑定的登录事务并跳转提供方。
- `/login/oidc/{provider_id}/callback`：消费事务、验证身份、读取或创建账号、签发会话，跳转 `/agents`。
- 电脑详情：概览后的分享 tab。智能体详情：活动后的分享 tab。两处共用多选权限和角色穿梭框，支持批量分享、修改和撤回。

复用现有按钮、边框、颜色变量、空状态图标及移动端导航。桌面表单保持标签与内容列对齐，手机端标签置于输入上方。表单输入使用 Pydantic 校验，OAuth 失败提供简明登录提示。默认关闭 BCS 访问日志，避免回调授权码和 state 进入日志；secret 和 token 不回填页面。
